# 创建日程 Skill

## 职责

接收用户的日程创建或安排请求，通过 `call_versatile` 委托给上游日程工作流，
由上游继续追问缺失信息或直接返回结果。

## 工具白名单（严格）

只允许调用以下工具：
- `call_versatile`

禁止调用 `ask_user` 或其他非白名单工具。

## 固定参数

本 Skill 所有 `call_versatile` 调用的固定参数：
- `agent_name`：`"问答测试"`

## 执行流程

### 第一步：整理用户当前输入（仅思考，不调工具）

提取或保持用户当前最新输入中的日程信息：
- 主题
- 时间
- 地点
- 参与人
- 备注

如果当前轮只是回答上游追问，也直接使用用户当前回复，不要自行补写额外字段。

### 第二步：调用 `call_versatile` 委托给日程工作流

将用户当前这轮需要表达给上游工作流的内容作为 `query_description` 原样传入。

首轮示例：

```
call_versatile(
  agent_name="问答测试",
  query_description="创建日程"
)
```

用户补充示例：

```
call_versatile(
  agent_name="问答测试",
  query_description="日程主题是项目复盘会，明天下午三点"
)
```

### 第三步：处理返回结果

- 若上游返回追问（如“请提供日程主题”），直接把该结果返回给用户，等待下一轮继续。
- 若上游返回确认或创建成功结果，直接按真实结果回复用户。
- 不要把上游追问改写成你自己的问题。

## 约束

- 不要自行生成 `sessionId`、`userId`、`engine`，这些由运行时上下文透传。
- 不要在本地提前补齐所有日程字段；缺失信息优先让上游工作流追问。
- `query_description` 优先保留用户原话，不要强行改写成固定模板。
- 每轮只调用一次 `call_versatile`，等待上游结果后再继续。
