# Dependency Management Rules

Root `pom.xml` is the canonical source of truth (versions in
`<properties>`, shared deps in `<dependencyManagement>`). Read it
directly; this doc encodes the reasoning.

## Core Rules

1. **All versions as `${property}`** in root pom, referenced by module
   poms — never hard-code versions in module `<dependency>` blocks.
   Exception documented below (agent-core literal version).
2. **One property per library family** — `${jackson.version}` covers all
   Jackson artifacts; never per-artifact properties.
3. **The agent-core-java pin is a literal, deliberate**: runtime keeps
   the literal `agent-core-java` version in `dependencyManagement` (see
   commit 0dbb804c) — Boot's property overriding must not silently
   retarget the core dependency. Do not "fix" it to a property without
   team agreement.
4. **Scope**: `test` for test-only, `optional` for opt-in extensions;
   demo modules depend on app/adapters normally.
5. **License**: Apache 2.0 / MIT / BSD-2 / EPL-LGPL compatible only;
   append to `Third_Party_Open_Source_Software_Notice.txt` when adding.

## Compatibility Matrix (must re-verify on upgrade)

The A2A SDK imposes cross-dependency constraints documented in root pom
comments — treat them as a checklist:

| Upgrade | Forced companion check | Reason |
|---|---|---|
| `a2a-sdk.version` | protobuf-java(-util) same version; gson ≥ 2.11.0 | SDK 1.0.0.Final wire code generated by protoc 4.x — protobuf 3.x dies at runtime (`NoSuchMethodError`); `JSONRPCUtils` needs `setStrictness` API |
| protobuf | keep java & java-util on the same version | util artifact must match core artifact |
| gson | re-run JSON-RPC id echo tests | numeric id fidelity depends on Gson parse behavior (GitCode !262) |
| agent-core-java | re-run full reactor tests + examples | runtime compiles against its API surface; check `Agent Core 依赖.md` |
| spring-boot | check auto-config imports file & property binding | `AutoConfiguration.imports` mechanism, `@ConditionalOnProperty` name matching |

**Rule**: an upgrade PR bundles the companion adjustments in one MR with
the matrix rows it satisfied — split "just bump the number" PRs are
rejected.

## SDK Vulnerability Watch

`a2a-sdk` 1.0.0.Final predates 1.3.0.Final security fixes
(task-store authorization fail-open CVE-2026-111764; push-notification
SSRF CVE-2026-111761). This repo mitigates the SSRF via its own
`HttpPushNotificationSender` + `A2aPushNotificationCallbackUrlPolicy`,
but the task-authorization gap is real in multi-caller deployments.
When upgrading to ≥ 1.3.0.Final: authorization becomes fail-closed
(`a2a.authorization.required`), plan the provider/opt-out decision —
see `.claude/test-scenarios/` and the CVE analysis in the team issue.

## Banned Patterns

| Banned | Use instead | Rule |
|---|---|---|
| New second JSON lib (beyond boundary Gson) | Jackson | json-serialization.md |
| New HTTP client for external calls | Existing adapter `ExternalCallExecutor` / JDK client where SDK requires | Single client per concern |
| `commons-lang3`, `commons-io` | JDK 17 native | Avoid Commons |
| `guava` | JDK 17 (`List.of`, `Map.of`) | Avoid Guava |
| `*-SNAPSHOT` dependencies | Release versions | Reproducible builds |
