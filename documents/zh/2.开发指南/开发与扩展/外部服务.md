# 外部服务

外部服务是 Agent 在执行过程中访问的进程外能力，例如 MCP 工具服务、远端 A2A Agent、Sandbox 沙箱服务等。
在 `agent-runtime-java` 中，外部服务能力位于 **Service Adapters** 层：它不把所有外部协议重新实现在 Agent Service 里，而是把配置、治理策略和 Core 扩展点接起来，让 Agent Core 在出站调用时拿到已经装饰过的客户端。

本文说明外部服务的概念边界、配置方式和本地验证路径。

## 1. 外部服务解决什么问题

Agent Service 的主路径是入站对话：

```text
Client -> /v1/query -> ServeOrchestrator -> AgentHandler -> Agent Core Runner
```

外部服务处理的是 Runner 运行中的出站调用：

```text
Agent Core Runner
  -> MCP Client / RemoteClient / SandboxClient
      -> Decorating Client
          -> 外部 MCP / A2A / Sandbox 服务
```

这层的价值主要有三点：

| 问题 | 外部服务 Adapter 的处理方式 |
| --- | --- |
| 配置分散 | 用 `openjiuwen.service.external.*` 统一声明外部服务地址和协议类型 |
| 缺少治理 | 对出站调用增加超时、重试、熔断、审计 |
| Core 接线复杂 | 在 Service 启动时注册 MCP / A2A remote provider；Sandbox 复用 agent-core-java 的 provider，只在 runtime 层创建 Core client |

需要注意：外部服务 Adapter 不负责实现真实 MCP Server、真实 A2A 对端或真实沙箱隔离。它负责把 Agent Service 接到这些外部系统。

## 2. 当前支持的外部服务

| 类型 | 配置前缀 | 作用 |
| --- | --- | --- |
| MCP | `openjiuwen.service.external.mcp` | 注册 MCP server，并让 Core 通过装饰后的 MCP client 调工具 |
| A2A Remote | `openjiuwen.service.external.remote` | 声明远端 A2A Agent，创建装饰后的 Core `RemoteClient` |
| Sandbox | `openjiuwen.service.external.sandbox` | 声明沙箱服务，映射 Core `SandboxGatewayConfig`，创建装饰后的 Core `SandboxClient` |

相关代码主要在：

```text
service/agent-service-adapters/agent-service-adapters-agentcore
└── src/main/java/com/openjiuwen/service/adapters/agentcore/external
```

关键对象：

| 类 | 说明 |
| --- | --- |
| `AgentCoreExternalProperties` | 绑定 `openjiuwen.service.external.*` 配置 |
| `DefaultExternalSvcAdapterRegistrar` | 向 Core 注册 MCP provider 和 A2A remote provider |
| `DefaultAgentCoreRemoteClientFactory` | 按 `remote.clients[].id` 创建 remote client |
| `DefaultAgentCoreSandboxClientFactory` | 校验 sandbox 配置，将 server 配置映射为 Core `SandboxGatewayConfig`，并创建 Core `SandboxClient` |
| `DecoratingMcpClient` / `DecoratingRemoteClient` / `DecoratingSandboxClient` | 执行超时、重试、熔断、审计等治理 |

## 3. 启动链路

使用默认 Core Handler 时，外部服务会跟随 `JiuwenCoreAgentHandler.start()` 注册：

```text
Agent Service 启动
  -> AgentLifecycleBootstrap
      -> AgentHandler.start()
          -> ExternalSvcAdapterRegistrar.registerToRunner()
          -> Runner.start()
```

`registerToRunner()` 会做两类事情：

1. 注册 MCP client provider：`sse`、`stdio`、`streamable_http`。
2. 注册 A2A remote provider：Core 创建 `RemoteClient` 时返回 `DecoratingRemoteClient`。

Sandbox 走另一条链路：`openjiuwen.service.external.sandbox.enabled=true` 时，自动装配会创建 `AgentCoreSandboxClientFactory` bean。`DefaultAgentCoreSandboxClientFactory` 构造时只校验 `servers[]`，不在 runtime 层注册 sandbox HTTP provider。

Sandbox client 是按需创建的。业务需要时注入 `AgentCoreSandboxClientFactory`，再调用 `create()` 或 `create(serverId)`，得到带超时、重试、熔断和审计包装的 `DecoratingSandboxClient`。底层 `fs`、`shell`、`code` 能力由 agent-core-java 的 sandbox provider 负责。

如果你提供了自定义 `@Bean AgentHandler`，默认 Core Handler 不会生效。此时需要你在自定义 Handler 中显式使用 `ExternalSvcAdapterRegistrar` 或相关 factory。

## 4. 通用治理策略

三类外部服务都支持类似的治理参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `timeout-ms` | `30000` | 单次外部调用超时时间 |
| `retry.max` | `0` | 最大重试次数；demo profile 常配置为 `1` |
| `retry.backoff-ms` | `0` | 重试间隔 |
| `circuit-breaker.enabled` | `false` | 是否启用熔断；demo profile 默认启用 |
| `circuit-breaker.failure-threshold` | `5` | 连续失败阈值 |
| `circuit-breaker.reset-timeout-ms` | `30000` | 熔断恢复等待时间 |
| `audit.enabled` | `true` | 是否记录外部调用审计日志 |

MCP 和 Remote 有额外的幂等控制：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `mcp.retry-tool-calls` | `false` | 是否重试 MCP `tools/call` |
| `remote.retry-invoke` | `false` | 是否重试 remote `invoke` |

工具调用和远端 Agent 调用可能产生副作用，因此默认不对核心调用自动重试。只有确认外部操作幂等时，才建议打开这两个开关。

## 5. 配置 MCP 外部服务

MCP 配置位于 `openjiuwen.service.external.mcp`。

最小配置：

```yaml
openjiuwen:
  service:
    external:
      mcp:
        timeout-ms: 30000
        retry-tool-calls: false
        retry:
          max: 1
          backoff-ms: 200
        circuit-breaker:
          enabled: true
          failure-threshold: 3
          reset-timeout-ms: 30000
        servers:
          - server-id: demo-mcp
            server-name: demo-mcp-tools
            server-path: http://localhost:18080/mcp
            client-type: streamable-http
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `server-id` | MCP server 标识，用于和 Core 配置匹配 |
| `server-name` | MCP server 名称，不能为空 |
| `server-path` | MCP server 地址，不能为空 |
| `client-type` | `sse`、`stdio`、`streamable-http` / `streamable_http` |
| `timeout-ms` | 可放在全局 MCP 策略，也可放在单个 server 上覆盖 |

### 本地验证 MCP

推荐从 `agent-runtime-java` 仓库根目录运行完整 smoke：

## 6. 配置 A2A Remote 外部服务

A2A Remote 配置位于 `openjiuwen.service.external.remote`，用于声明可被 Core `RemoteClientFactory` 创建的远端 Agent。

最小配置：

```yaml
openjiuwen:
  service:
    external:
      remote:
        clients:
          - id: demo-a2a-remote
            name: Demo A2A Remote
            protocol: A2A
            url: http://127.0.0.1:18082
        timeout-ms: 3000
        retry-invoke: false
        retry:
          max: 1
          backoff-ms: 200
        circuit-breaker:
          enabled: true
          failure-threshold: 3
          reset-timeout-ms: 30000
        audit:
          enabled: true
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `clients[].id` | 远端客户端标识，不能为空 |
| `clients[].name` | 远端客户端名称 |
| `clients[].protocol` | 当前只支持 `A2A` |
| `clients[].url` | 远端 A2A 服务地址，必须是 `http` 或 `https` URL |
| `clients[].timeout-ms` | 单个远端客户端的超时覆盖值 |

`url` 校验只接受 HTTP(S)。如果写成空值、非 HTTP scheme，应用启动或 factory 创建阶段会失败。

### 本地验证 A2A Remote

从 `agent-runtime-java/service` 编译示例：

```bash
mvn -pl agent-service-demo -am -DskipTests clean install
mvn -pl agent-service-demo dependency:build-classpath \
```

```bash
  com.openjiuwen.service.demo.example.remote.MockA2ARemoteServerExample \
  --port=18082
```

运行 remote client 调用示例：

```bash
java -cp "agent-service-demo/target/example-classes:$EXAMPLE_CP" \
  com.openjiuwen.service.demo.example.remote.A2ARemoteAdapterExample \
  --client-id=demo-a2a-remote \
```


如果业务代码想直接按配置创建 remote client，可以注入：

```java

```

## 7. 配置 Sandbox 外部服务

Sandbox 配置位于 `openjiuwen.service.external.sandbox`。runtime 不启动真实沙箱，也不实现独立的 sandbox HTTP provider；它负责把 Service 配置映射为 Core `SandboxGatewayConfig`，再交给 agent-core-java 的 sandbox provider 访问外部沙箱服务。

对于 `jiuwenbox` 类型，后端协议由 agent-core-java 负责，标准后端入口是服务基地址下的 `/api/v1/sandboxes`。runtime 文档不再描述旧 HTTP provider 协议。

最小配置：

```yaml
openjiuwen:
  service:
    external:
      sandbox:
        enabled: true
        timeout-ms: 30000
        retry:
          max: 1
          backoff-ms: 200
        circuit-breaker:
          enabled: true
          failure-threshold: 3
          reset-timeout-ms: 30000
        audit:
          enabled: true
        servers:
          - server-id: default
            service-url: http://127.0.0.1:8321
            sandbox-type: jiuwenbox
            launcher-type: pre_deploy
            on-stop: delete
            root-path: .
```

带隔离和自定义参数的配置示例：

```yaml
openjiuwen:
  service:
    external:
      sandbox:
        enabled: true
        timeout-ms: 30000
        servers:
          - server-id: default
            service-url: http://127.0.0.1:8321
            sandbox-type: jiuwenbox
            launcher-type: pre_deploy
            on-stop: delete
            root-path: /workspace
            isolation-key: session-1
            isolation-prefix: tenant-a
            container-scope: CUSTOM
            idle-ttl-seconds: 600
            timeout-ms: 5000
            extra-params:
              sandbox_id: sbx-1
```

字段说明：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否启用 sandbox factory。 |
| `timeout-ms` | `30000` | sandbox 全局调用超时，最终转换为 Core `timeoutSeconds`。 |
| `servers[].server-id` | 无 | 沙箱服务标识；`create(null)` 或 `create("")` 使用第一个 server。 |
| `servers[].service-url` | 无 | 沙箱服务基地址，必须是 `http` 或 `https` URL；会写入 Core gateway / launcher URL。 |
| `servers[].sandbox-type` | `jiuwenbox` | Core sandbox provider 类型；runtime 不注册 provider，只把类型传给 Core。 |
| `servers[].launcher-type` | `pre_deploy` | 写入 Core `SandboxLauncherConfig.launcherType`。 |
| `servers[].on-stop` | `delete` | 写入 Core `SandboxLauncherConfig.onStop`。 |
| `servers[].root-path` | `.` | 如果 `params.root_path` 未显式设置，则写入 Core gateway `params.root_path`。 |
| `servers[].isolation-key` | 空 | 写入 Core `SandboxIsolationConfig.customId`。 |
| `servers[].isolation-prefix` | 空 | 写入 Core `SandboxIsolationConfig.prefix`。 |
| `servers[].container-scope` | `SESSION` | 写入 Core `SandboxIsolationConfig.containerScope`。 |
| `servers[].timeout-ms` | 空 | 覆盖该 server 的 sandbox 调用超时。 |
| `servers[].idle-ttl-seconds` | 空 | 写入 Core `SandboxLauncherConfig.idleTtlSeconds`。 |
| `servers[].params` | `{}` | 写入 Core `SandboxGatewayConfig.params`，用于传递 Core provider 支持的扩展参数。 |
| `servers[].extra-params` | `{}` | 写入 Core `SandboxLauncherConfig.extraParams`，用于传递 launcher/provider 扩展参数。 |

`enabled=true` 时必须至少配置一个 server，且 `server-id`、`service-url`、`sandbox-type` 不能为空；全局或 server 级 `timeout-ms` 必须大于 0，否则应用启动会失败。

### 沙箱协议边界

runtime 只创建 Core `SandboxClient`，不再定义额外的 sandbox HTTP 协议，也不再提供本地 mock sandbox server。`SandboxClient.fs()`、`shell()`、`code()` 的实际 HTTP 请求路径、请求体和响应体由 agent-core-java 中对应 `sandbox-type` 的 provider 决定。

因此 `service-url` 应填写 provider 所需的服务基地址。例如 `sandbox-type=jiuwenbox` 时，
`service-url=http://127.0.0.1:8321` 表示 Core provider 会访问该服务下的 JiuwenBox 标准接口。

### 本地验证 Sandbox

Runtime 不提供本地 mock Sandbox 后端或 Adapter 直连示例。先按照 JiuwenBox 文档在 Linux 或容器环境

```bash

```

从 `agent-runtime-java/service` 运行环境 smoke：

```bash

```


JiuwenBox；因此它属于已准备外部服务的环境冒烟，不属于无依赖的普通单元测试。

## 8. 生产化检查清单

上线前至少确认这些点：

| 检查项 | 说明 |
| --- | --- |
| URL 合法性 | Remote 和 Sandbox 只接受 `http` / `https` URL |
| 幂等性 | 只有确认工具或远端调用幂等时才开启 `retry-tool-calls` / `retry-invoke` |
| 超时 | 根据外部服务 SLA 调整 `timeout-ms`，避免 Agent 请求无限等待 |
| 熔断 | 对不稳定外部系统启用 circuit breaker，防止故障扩散 |
| 审计 | 生产默认保留 `audit.enabled=true`，方便定位出站调用问题 |
| 密钥 | 外部服务密钥放环境变量或配置中心，不写入仓库 |
| 自定义 Handler | 如果不用 `JiuwenCoreAgentHandler`，需要自己接入 registrar 或 factory |
| Sandbox 安全 | runtime 不提供隔离实现；生产需要接入具备真实隔离、权限和资源限制的 sandbox 后端 |
| 出站 TLS / 鉴权 | MCP / Remote / Sandbox 的 `tls` / `auth` 子配置见 [§9](#9-出站-tls-与鉴权-issue-25)；生产 token 用 `encrypted-token` |

## 9. 出站 TLS 与鉴权（Issue #25）

Adapters 在注册 MCP / 创建 Remote / Sandbox client 时，可为每个 endpoint 配置 **出站传输安全** 与 **HTTP 鉴权叠加物**（headers / query）。默认不配置时行为与改造前一致。

### 9.1 配置前缀

| 外部服务 | endpoint 路径 | TLS / Auth 挂载点 |
| --- | --- | --- |
| MCP | `openjiuwen.service.external.mcp.servers[]` | 每个 `server-id` 下的 `tls` / `auth` |
| A2A Remote | `openjiuwen.service.external.remote.clients[]` | 每个 `id` 下的 `tls` / `auth` |
| Sandbox | `openjiuwen.service.external.sandbox.servers[]` | 每个 `server-id` 下的 `tls` / `auth` |

### 9.2 TLS 字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否启用出站 TLS 客户端 |
| `ref` | `inline` | `global` 时复用 `openjiuwen.service.security.tls.*`（与 Issue #24 入站共用前缀） |
| `verify-hostname` | `true` | 是否校验服务端主机名 |
| `key-store` | — | 客户端身份证书（mTLS） |
| `key-store-password` | — | 客户端 keystore 密码，生产用 `ENC(...)` |
| `trust-store` | — | 信任 CA / 服务端证书 |
| `trust-store-password` | — | truststore 密码 |
| `key-store-type` / `trust-store-type` | — | 如 `PKCS12` |
| `enabled-protocols` | — | 如 `[TLSv1.2, TLSv1.3]` |

`tls.enabled=true` 且 `ref=inline` 时须至少配置 `key-store` 或 `trust-store`。MCP `client-type=stdio` 不支持 TLS。

### 9.3 Auth 字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `type` | `none` | `none` / `bearer` / `header` / `custom` |
| `header-name` | `Authorization` | `type=header` 时的 header 名 |
| `token` | — | 明文 token（仅 demo / 本地） |
| `encrypted-token` | — | 密文 token，经 `CredentialDecryptor` 按 MCP/Remote/Sandbox 场景解密 |
| `credentials-ref` | — | 预留凭据引用 |
| `extensions` | `{}` | 传给 `ExternalAuthenticator` SPI 的扩展参数 |

`type=custom` 时由接入方实现 `@Bean ExternalAuthenticator` 产出 `AuthMaterial`。

### 9.4 MCP HTTPS + Bearer 示例

```yaml
openjiuwen:
  service:
    external:
      mcp:
        servers:
          - server-id: bank-mcp
            server-path: https://mcp.internal/sse
            client-type: sse
            tls:
              enabled: true
              ref: global
              verify-hostname: true
            auth:
              type: bearer
              encrypted-token: ENC(...)
```

全局 TLS 材料（`ref: global`）示例：

```yaml
openjiuwen:
  service:
    security:
      tls:
        enabled: true
        key-store: file:/etc/agent/tls/outbound-client.p12
        key-store-password: ENC(...)
        trust-store: file:/etc/agent/tls/external-ca.p12
        trust-store-password: ENC(...)
```

### 9.6 Auth 合并顺序与错误语义

**材料合并**（`ExternalAuthMaterialMerger`）：

1. 根据 `auth.type` 构建内置材料（`bearer` → `Authorization: Bearer …`；`header` → 自定义 header）。
2. 若存在 `ExternalAuthenticator` Bean，调用 SPI 获取 overlay 材料。
3. 合并 headers / query：**同名 key 以 SPI 产出覆盖内置值**。
4. `auth.type=custom` 时不构建内置材料，完全依赖 SPI。
5. `auth.type` 非 `none` 且合并后材料为空 → 抛出 `ExternalAuthenticationException`，出站调用失败。

**stdio MCP + TLS**：`client-type=stdio` 时 endpoint 上的 `tls` 配置会被忽略，并输出 warn 日志（stdio 无 HTTP 传输层）。

**错误码**（`ExternalSvcAdapterErrorCode`）：

| 码 | 含义 |
| --- | --- |
| `EXT_MCP_005` | MCP 出站 TLS 握手失败 |
| `EXT_MCP_006` | MCP 出站鉴权失败 |
| `EXT_REMOTE_006` | Remote 出站 TLS 握手失败 |
| `EXT_REMOTE_007` | Remote 出站鉴权失败 |
| `EXT_SANDBOX_005` | Sandbox 出站 TLS 握手失败 |
| `EXT_SANDBOX_006` | Sandbox 出站鉴权失败 |

入站 TLS / 细粒度鉴权见 [安全加固](安全加固.md)。
