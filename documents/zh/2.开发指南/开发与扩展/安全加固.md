# 安全加固

本文说明 Agent Service **入站**（Issue #24）与 **出站**（Issue #25）安全能力：传输层 TLS/mTLS、细粒度鉴权 SPI、出站 HTTP 客户端 TLS/鉴权，以及两者在 `TlsMaterial` / `openjiuwen.service.security.tls.*` 上的对称关系。

> 出站 per-endpoint 配置与 E2E 验证见 [外部服务 §9](外部服务.md#9-出站-tls-与鉴权-issue-25)。入站 auth demo 见 [agent-service-demo/example/security/README.md](../../../../service/agent-service-demo/example/security/README.md)。

## 1. 能力边界

| 层级 | Issue | 作用域 | 机制 |
| --- | --- | --- | --- |
| **L0 传输** | #24 | 入站 HTTP/A2A | `openjiuwen.service.security.tls.*` → Spring `server.ssl.*`；支持 HTTPS / 单向 TLS / mTLS（`client-auth: none\|want\|need`） |
| **L1 鉴权** | #24 | 入站 REST / A2A | `FineGrainedAuthorizer` SPI + `@AuthorizedResource` + `ResourceAuthorizationAspect`；拒绝返回 **403** |
| **出站 TLS** | #25 | MCP / Remote / Sandbox | 每个 endpoint 的 `tls.*`；`ref: global` 复用 #24 全局材料 |
| **出站鉴权** | #25 | MCP / Remote / Sandbox | 每个 endpoint 的 `auth.*` + `ExternalAuthenticator` SPI |

**对称关系**：入站 `FineGrainedAuthorizer` ↔ 出站 `ExternalAuthenticator`；入站/出站 TLS 材料共用 `com.openjiuwen.service.spec.security.TlsMaterial` 与 `openjiuwen.service.security.tls.*` 前缀。

## 2. 配置开关与默认行为

所有安全能力默认 **关闭**。未开启时行为与 v0.1.0 完全一致。

| 开关 | 前缀 / 属性 | 作用 |
| --- | --- | --- |
| 总开关 | `openjiuwen.service.security.enabled` | `false` 时不注册 TLS 绑定与鉴权 AOP |
| 入站 TLS | `openjiuwen.service.security.tls.enabled` | 映射 `server.ssl.*` |
| 入站鉴权 | `openjiuwen.service.security.auth.enabled` | 启用 `@AuthorizedResource` AOP |

## 3. 入站 TLS / mTLS（Issue #24）

### 3.1 配置项

前缀：`openjiuwen.service.security.tls`

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否启用入站 TLS |
| `protocol` | `TLS` | SSL 上下文协议 |
| `enabled-protocols` | `[TLSv1.2, TLSv1.3]` | 允许的协议版本 |
| `client-auth` | `none` | mTLS 模式：`none` / `want` / `need` |
| `key-store` | — | 服务端身份证书（`tls.enabled=true` 时必填） |
| `key-store-password` | — | keystore 密码；生产用密文，场景 `TLS_KEYSTORE_PASSWORD`(13) |
| `key-store-type` | `PKCS12` | keystore 类型 |
| `trust-store` | — | `client-auth=want\|need` 时必填 |
| `trust-store-password` | — | truststore 密码，场景 `TLS_TRUSTSTORE_PASSWORD`(14) |
| `trust-store-type` | `PKCS12` | truststore 类型 |
| `certificate-expiry-policy` | `warn` | 证书过期：`warn` 仅告警；`fail` 启动失败 |

启动时 `TlsStartupValidator` 校验 keystore/truststore 可读性、证书是否过期（按 `certificate-expiry-policy`）。

### 3.2 示例

```yaml
openjiuwen:
  service:
    security:
      enabled: true
      tls:
        enabled: true
        client-auth: need
        key-store: file:/etc/agent/tls/server.p12
        key-store-password: ENC(...)
        trust-store: file:/etc/agent/tls/client-ca.p12
        trust-store-password: ENC(...)
        certificate-expiry-policy: fail
```

完整注释模板见 `agent-service-demo/example/security/application-security-tls.example.yml`。

## 4. 入站细粒度鉴权（Issue #24）

### 4.1 SPI 与 AOP

1. 在 Controller 方法上标注 `@AuthorizedResource(resource = "...", action = "...")`。
2. `ResourceAuthorizationAspect` 在方法执行前调用 `FineGrainedAuthorizer.authorize(AuthorizationRequest)`。
3. `AuthorizationRequest` 含 `resource`、`action`、`userId`、`spaceId`、`tenantId` 及 HTTP 扩展参数。
4. 租户字段来源：请求体 / Query 参数，或 Header `X-User-ID` / `X-Space-ID` / `X-Tenant-ID`（Header 非空时覆盖 body）。

接入方实现 **唯一** 一个 `@Bean FineGrainedAuthorizer`（对接 IAM / RBAC / ABAC）。`auth.enabled=true` 时若缺少或存在多个 Bean，启动 fail-fast（`FineGrainedAuthorizerBootstrapValidator`）。

### 4.2 受保护端点与默认 resource/action

| 端点 | resource | action | 说明 |
| --- | --- | --- | --- |
| `POST /v1/query`、`/query`、`/v1/query/reactive` | `query` | `execute` | Query 执行 |
| `POST /v1/reset_conversation`、`/reset_conversation` | `session` | `reset` | 会话重置 |
| `POST /a2a`、`/a2a/` | `a2a` | `rpc` | A2A JSON-RPC |
| `GET /.well-known/agent-card.json` 等 Agent Card | `agent-card` | `read` | 能力发现 |
| A2A Push Callback | `a2a-push-callback` | `receive` | 异步回调接收 |
| `GET /health` | — | — | **不受** 鉴权 AOP 影响 |

### 4.3 403 响应契约

鉴权拒绝时 HTTP **403**，JSON body：

```json
{
  "type": "error",
  "error": "access denied",
  "code": "ACCESS_DENIED",
  "resource": "query",
  "action": "execute",
  "reason": "optional human-readable detail"
}
```

`reason` 仅在 Authorizer 返回时存在。由 `AuthorizationDeniedExceptionHandler` 统一映射。

### 4.4 示例

```yaml
openjiuwen:
  service:
    security:
      enabled: true
      auth:
        enabled: true
```

```java
@Bean
FineGrainedAuthorizer demoAuthorizer() {
    return request -> {
        if (request.getUserId() == null || request.getUserId().isBlank()) {
            return AuthorizationResult.denied("missing user id");
        }
        return AuthorizationResult.allowed();
    };
}
```

本地验证：`mvn -pl agent-service-demo/example/security -am spring-boot:run`（端口 8095）。

## 5. 出站安全（Issue #25 摘要）

出站 TLS/鉴权挂载在 `openjiuwen.service.external.{mcp,remote,sandbox}.*[].tls` / `auth` 上。要点：

- **`tls.ref: global`**：复用 §3 的全局 `openjiuwen.service.security.tls.*` 材料。
- **Auth 合并顺序**：先构建内置 bearer/header 材料，再与 `ExternalAuthenticator` SPI 产出合并；**同名 header/query 以 SPI 覆盖**内置值。
- **`auth.type=custom`**：仅走 SPI，内置 bearer/header 不生效。
- **失败语义**：`auth.type` 非 `none` 且合并后材料为空 → 抛出 `ExternalAuthenticationException`，出站调用失败。
- **stdio MCP + TLS**：TLS 配置会被 **忽略** 并输出 warn 日志（stdio 无 HTTP 传输层）。
- **错误码**：`EXT_MCP_005/006`、`EXT_REMOTE_006/007`、`EXT_SANDBOX_005/006`（TLS 握手 / 出站鉴权失败）。

详见 [外部服务 §9](外部服务.md#9-出站-tls-与鉴权-issue-25) 与 [Adapters 与 Handler §出站安全](../Adapters与Handler.md#出站安全-issue-25)。

## 6. 凭据解密场景

`CredentialDecryptor.decrypt(ciphertext, sceneType)` 使用稳定场景常量（`CredentialSceneType`）：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `UNKNOWN` | 0 | 未区分场景 |
| `REDIS_PASSWORD` | 1 | Redis 密码 |
| `LLM_API_KEY` | 2 | LLM API Key |
| `MEMORY_API_KEY` | 3 | mem0 等记忆服务 |
| `MCP_AUTH_TOKEN` | 10 | MCP 出站 token |
| `REMOTE_AUTH_TOKEN` | 11 | Remote(A2A) 出站 token |
| `SANDBOX_AUTH_TOKEN` | 12 | Sandbox 出站 token |
| `TLS_KEYSTORE_PASSWORD` | 13 | TLS keystore 密码 |
| `TLS_TRUSTSTORE_PASSWORD` | 14 | TLS truststore 密码 |
