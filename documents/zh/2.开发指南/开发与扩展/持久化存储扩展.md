# 持久化存储扩展

`openjiuwen.service.middleware.checkpointer.type` 同时选择 Core 检查点和 A2A TaskStore。
内置 `in_memory`、`redis` 保留原有路径，Redis 继续使用 `redis-ref` 和正数 `ttl-seconds`。
其它类型由应用提供两个 Spring Bean：

| 接口 | 方法与职责 |
| --- | --- |
| `com.openjiuwen.service.adapters.agentcore.middleware.CheckpointKVStoreProvider` | `type()` 返回类型名，`getStore(connectionRef)` 返回初始化完成的异步 Core KVStore |
| `com.openjiuwen.service.app.storage.A2ATaskStoreProvider` | `type()` 返回同一类型名，`create(context)` 按作用域创建原始 SDK TaskStore |

异步 KVStore 是 `com.openjiuwen.core.foundation.store.BaseKVStore`；这里的 Provider 与
Core 同步存储 SPI `com.openjiuwen.spi.store.KVStoreProvider` 无关。
数据库驱动、连接池、SQL、建表及连接参数由应用负责，Runtime 不默认支持具体数据库。

```yaml
openjiuwen:
  service:
    middleware:
      checkpointer:
        type: customdb
        connection-ref: default
```

每个扩展类型在两个接口上分别要求恰好一个匹配 Bean；缺失、重复、返回 null 都报错。
未知类型不回退内存。`connection-ref` 默认 `default`，应用可在自己的配置子树中定义命名连接。
显式提供的普通模式 TaskStore Bean 仍沿用现有替换约定；Hosted 不接受全局 TaskStore 替换。

注册 Bean 的自动配置应通过 `@AutoConfiguration(beforeName = {...})` 排在
`com.openjiuwen.service.adapters.agentcore.autoconfigure.MiddlewareAdaptersAutoConfiguration`、
`com.openjiuwen.service.app.autoconfigure.A2AAutoConfiguration` 和
`com.openjiuwen.service.app.autoconfigure.HostedRuntimeAutoConfiguration` 之前，并加入应用 JAR 的
`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`。
普通 Spring `@Configuration` 的业务 Bean 也可使用，无需覆盖框架 Bean。

框架从 Checkpoint Provider 获取一次 Store，创建 `type=persistence`、`conf.kv_store=<Store>`
的 Core 配置。现有 `MiddlewareAdapterRegistrar` 在 Runner 启动前重用该配置；自定义 Handler
也应将该 Registrar 传给支持它的 Core Handler 构造方法。

`TaskStoreContext` 是接口内嵌的不可变 record，含 `applicationName`、稳定的 `agentId`、
`connectionRef` 和 `onClose`。普通模式优先使用 `openjiuwen.service.agent-id`，未设置时使用
`spring.application.name`；Hosted 使用注册的每个 `Entry.agentId()`。Store 应使用 agentId
约束其全部读写，多个 Hosted Agent 可以共用表。独立应用需要共享数据库时，由应用规划身份与隔离。

Task Provider 返回未经节流包装的 Store，框架统一加一层 `WriteThrottlingTaskStore`，保留
`TaskStateProvider` 行为。作用域独有资源可在 `create()` 内通过
`context.onClose().accept(resource::close)` 登记，创建失败和关闭时均执行；共享连接池由应用统一关闭。
不要将共享池的关闭登记到单个 Agent。Core 可能在更换 Checkpointer 时调用 KVStore.close()，
借用共享资源的 Store 不应据此关闭应用资源。

KVStore 需实现 set、exclusiveSet、get、exists、delete、getByPrefix、deleteByPrefix、mget、
batchDelete、pipeline。检查点的二进制载荷和序列化标记须无损保存；pipeline 必须维持读写顺序，
检查点成对写入需具备事务原子性，配套读取需使用一致快照。mget 保持输入顺序、重复键和空位；
前缀中的通配符应按字面处理，空前缀表示全部 key。临时操作的显式期限与普通会话保存期限分别处理。

TaskStore 实现 SDK 的 `save(Task, boolean isReplicated)`、`get(taskId)`、`delete(taskId)` 和
`list(ListTasksParams)`。save 的 boolean 表示复制来源；它不是覆盖写开关。完整 Task JSON、
列表过滤/排序/PageToken/投影应与 SDK 契约一致，读取错误不能伪装成未命中。

扩展 SPI 随统一构建发布，本特性不自行调整版本号。本地联调可覆盖同坐标 JAR；独立构建时须使用包含接口的统一产物。未知 type 由回退内存改为明确报错是有意兼容性变化。

Checkpointer 的 type 仅选择检查点与 Task；依赖 RedisClient 的会话归属、轨迹等扩展仍须独立提供其客户端。配置 redis 连接子树本身不保证客户端创建。部署应核对这些能力，不因后端切换静默降低隔离要求。
