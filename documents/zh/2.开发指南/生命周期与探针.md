# 生命周期与探针

Agent Service 在 Spring 容器启停时执行 **Init / Shutdown**，通过 `GET /health` 暴露就绪状态，并支持进程内 **interrupt**（停止当前流式执行，**无独立 REST**）。

与 **业务中断-恢复**（`QueryChunk` 类型 `interrupt`、`a2a_delegate`）及 **A2A Cancel** 不同，见下文「三种中断语义」。

## 生命周期阶段

```text
Spring ContextRefreshed
  → AgentLifecycleBootstrap
  → DefaultAgentLifecycleManager.runInitPhase()
      → InitPhaseExecutor
          → AgentInitHook（@Order）
          → AgentHandler.start()     # Core 路径：middleware/external 注册 + Runner.start()
          → agent_loaded = true/false

Spring ContextClosed
  → runShutdownPhase()
      → ShutdownPhaseExecutor
          → 等待活动流（shutdown-timeout-ms）
          → AgentHandler.stop()
          → AgentShutdownHook
```

- 无 `AgentHandler` Bean 时：Init 结束但 `agent_loaded=false`。
- `init-fail-fast=true`（默认）：Init 抛错则启动失败；`false` 时仅保持 `agent_loaded=false`。

## 就绪与探针

| 信号 | 含义 | HTTP 字段 |
| --- | --- | --- |
| 进程存活 | Spring 已启动 | `process_up` |
| Agent 可接单 | Init 完成且 Handler 就绪 | `agent_loaded` |

**K8s 建议**：

- liveness → `process_up`
- readiness → `agent_loaded`

```bash
curl -s http://localhost:8090/health
```

部署后 Manager / 网关可探测 `GET /health`；**服务注册与对外 URL** 不在 Agent 进程内完成。

## SPI 扩展

| 接口 | 用途 |
| --- | --- |
| `AgentInitHook` | 预热、校验外部依赖 |
| `AgentShutdownHook` | 释放连接、刷盘 |
| `AgentInterruptHandler` | 收到 lifecycle interrupt 后的业务清理 |
| `AgentReadiness` | 扩展就绪判断（默认 `DefaultAgentReadiness`） |

Hook 由 Spring 收集；`AgentInterruptHandler.interrupt(id, InterruptReason)` 中 reason 为 `LIFECYCLE_INTERRUPT`。

## 流式执行注册

```text
ServeOrchestrator.streamQuery
  → ActiveStreamRegistry.register(conversationId, handle)
  → AgentHandler.streamQuery(observer 包装 isCancelled)
  → onComplete / onError / cancel → unregister
```

`DefaultServeOrchestrator` 在 `conversationId` 维度注册活动流；`cancelActive(conversationId)` 触发 `CancellationException`，Observer 侧停止下发 chunk。

## 三种中断语义

| 类型 | 触发方式 | 作用 | 会话状态 |
| --- | --- | --- | --- |
| **Lifecycle interrupt** | `AgentLifecycleManager.interrupt(conversationId)`（进程内 API，无 HTTP） | 取消当前流式 run | 一般保留；不清 Checkpointer |
| **reset_conversation** | `POST /v1/reset_conversation` | `cancelActive` + `Handler.clearSession` | 清空会话上下文 |
| **业务 interrupt** | Handler 发出 `QueryChunk("interrupt", …)` | Orchestrator 路由（如 `a2a_delegate` 调远端、`ask_user` 返回客户端） | 由业务与 TaskStore 决定 |
| **A2A Cancel** | JSON-RPC → `A2AAgentExecutor.cancel` | `orchestrator.cancelActive(contextId)` + emitter cancel | 停止当前 A2A 流式执行 |

### Lifecycle interrupt 调用链

```text
AgentLifecycleManager.interrupt(conversationId)
  → ActiveStreamInterruptor
      → ServeOrchestrator.cancelActive(conversationId)
      → ActiveStreamRegistry.cancel → 流式 Observer 停止
      → AgentInterruptHandler（LIFECYCLE_INTERRUPT）
```

应用内可通过注入 `AgentLifecycleManager` 调用；**未暴露** `/interrupt` REST。

### 业务中断-恢复（Orchestrator）

启用 A2A 增强编排器时，`A2AEnabledServeOrchestrator` 在 `streamQuery` / `query` 循环中处理 `interrupt` chunk（`a2a_delegate`、`ask_user`、影子 Task 等）。这是 **协作式中断**，不是 lifecycle cancel。

详见 [A2A 开发指导 · 中断-恢复链](A2A开发指导.md#中断-恢复链)。

### A2A Cancel

A2A SDK 调用 `AgentExecutor.cancel` 时：

```text
A2AAgentExecutor.cancel
  → orchestrator.cancelActive(contextId)
  → emitter.cancel()
```

与 lifecycle interrupt 共用 `cancelActive`，但入口来自 **A2A JSON-RPC**，`contextId` 通常对应 `conversationId`。

## reset_conversation 与 interrupt 的关系

`ServeOrchestrator.resetConversation`（HTTP reset 入口）内部：

```text
cancelActive(conversationId) → AgentHandler.clearSession(conversationId)
```

即先停流，再清会话。见 [HTTP 对话面 · reset](HTTP对话面.md#post-reset_conversation)。

## 配置

前缀 `openjiuwen.service.lifecycle`（`LifecycleProperties`）：

| 属性 | 默认 | 说明 |
| --- | --- | --- |
| `shutdown-timeout-ms` | `30000` | Shutdown 等待活动流结束的最长时间（毫秒） |
| `init-fail-fast` | `true` | Init 阶段异常是否导致应用启动失败 |

示例见 [开发 Agent Service](开发Agent Service.md) 中的推荐 `application.yml`。

## Handler 启停

| 方法 | 时机 | Core 路径典型行为 |
| --- | --- | --- |
| `start()` | Init 成功路径 | middleware/external 注册 + `Runner.start()` |
| `stop()` | Shutdown | `Runner.stop()` 等 |
| `clearSession(id)` | reset HTTP | `Runner.release` 等 |

**非 Core 后端** 自定义 Handler 时不应盲目调用 `Runner.start()`。
