# 出站委派与流式规则

当你的 Agent（A）在工具里委派另一个远端 Agent（B）时，运行时需要决定：**远端 B 产生的消息要不要投影给最终客户端**，以及**哪一条结果回喂给 A 的模型**。本文描述这套对外可观测的行为契约与你需要做的配置，不涉及内部实现。

配置与整体调用链见 [A2A 开发指导](开发指导.md)。

## 投影条件

只有以下两个条件同时成立，Runtime 才使用流式 A2A 调用下游并投影其过程事件：

1. 目标 Agent 的 `a2a.remote-agents[].streaming` 配置为 `true`。
2. 当前上游请求本身为流式，例如 A2A `SendStreamingMessage` 或 REST `stream=true`。

| 上游请求 | 下游路由 `streaming` | 实际下游调用 | 下游事件投影给客户端 |
| --- | --- | --- | --- |
| 流式 | `true` | 流式 | 是 |
| 流式 | `false` | 非流式 | 否 |
| 非流式 | `true` | 非流式 | 否 |
| 非流式 | `false` | 非流式 | 否 |

该规则逐跳生效。A 流式调用 B，不代表 B 一定流式调用 C；B 到 C 仍需同时满足 B 当前请求为流式且 C 的远端路由启用 streaming。

## 如何配置

在目标 Agent 的远端目录项上声明是否允许流式调用：

```yaml
openjiuwen:
  service:
    a2a:
      remote-agents:
        - name: agentb
          card-url: http://127.0.0.1:18091/.well-known/agent-card.json
          streaming: true
```

该配置只表示目标支持流式调用。最终是否实际使用流式协议，仍由当前上游请求共同决定；不需要在 AgentCore 中断上下文里增加额外流式字段。

## 客户端能看到什么

实际下游调用为流式时，Runtime 将下游过程投影为父 Task 的 Artifact：

- `agentEvent.type=delegation`：当前 Runtime 到直接下游的委派边，并携带对应 `toolCallId`。
- `agentEvent.type=output`：下游业务 Artifact；已有合法 `agentEvent` 时逐跳保留。
- `agentEvent.type=status`：下游 Task 状态。

投影事件的外层 Task 仍属于当前父 Runtime，下游 Agent/Task 身份位于 `artifact.metadata.agentEvent`。

实际下游调用为非流式时，不投影 A 到 B 的 delegation，也不回放 B 最终 Task 快照中的 Artifact 或状态。Runtime 仍会从该 Task 形成 `RemoteCallOutcome`，用于结果汇聚、回喂模型和后续恢复。

## 结果如何回喂

流式与非流式下游使用同一终态结果选择规则。过程 Artifact 只用于流式观察，不能单独代表远端调用完成；Runtime 等待远端 Task 的终态或 `INPUT_REQUIRED` 等可恢复状态后形成 `RemoteCallOutcome`，再按原 `toolCallId` 汇聚并回喂 A。

## 中断与恢复

远端 B 需要更多输入时会返回 `INPUT_REQUIRED`，运行时保存远端 Task ID 和批次成员状态，并向客户端抛出统一中断，等待下一轮同一 `conversationId` 的请求继续。续轮是否投影下游过程，仍由续轮上游请求和远端路由配置共同决定。

你无需手动维护任何恢复状态，只要下一轮请求带上相同的 `conversationId` 即可续接。

## 小结与注意事项

- 下游事件投影条件是“上游请求流式”且“下游路由启用 streaming”。
- 非流式下游只返回 outcome，不产生 delegation、output 或 status 投影。
- 是否投影不改变最终结果回喂、`INPUT_REQUIRED`、shadow Task、批次恢复和结果 fan-in。
