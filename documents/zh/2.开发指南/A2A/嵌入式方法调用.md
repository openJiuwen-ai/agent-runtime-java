# 嵌入式 A2A 方法调用

客户已有 Spring Boot Web 应用时，直接依赖 `com.openjiuwen:agent-service-app`，保留客户唯一的 `SpringApplication.run(...)` 和 `AgentHandler` Bean。Runtime 的自动配置在同一个 Spring 容器内提供 `A2aRuntimeInvoker`，不需要再启动 Runtime 应用，也不需要扫描 Runtime 包。

```yaml
openjiuwen:
  service:
    http:
      enabled: false
```

此开关默认 `true`。设置为 `false` 后，Runtime 自带 REST、A2A JSON-RPC、AgentCard、探针、callback Controller 及相应入站鉴权/TLS 装配关闭。客户 Web 端口和自己的 Controller 继续工作，出站模型/A2A 调用、TaskStore 和生命周期保留。它不修改 `server.port` 或 `WebApplicationType`。整个应用都不需要端口时，宿主另设 `spring.main.web-application-type=none`。

## Java 接口

```java
import com.openjiuwen.service.app.invocation.A2aInvocationRequest;
import com.openjiuwen.service.app.invocation.A2aRuntimeInvoker;
import java.util.Map;
import java.util.concurrent.Flow;
import org.springframework.stereotype.Service;

@Service
public class CustomerAgentService {
    private final A2aRuntimeInvoker invoker;

    public CustomerAgentService(A2aRuntimeInvoker invoker) {
        this.invoker = invoker;
    }

    public Flow.Publisher<String> invoke(String jsonRpc, String userId) {
        return invoker.invoke(new A2aInvocationRequest(
                null, jsonRpc, Map.of("x-user-id", userId)));
    }
}
```

`A2aInvocationRequest(agentId, jsonRpcRequest, headers)` 是 Java 请求载体。`agentId=null` 选择默认 Agent；显式 ID 用于已有 `HostedAgentDefinitions` 多 Agent 托管。非 hosted 单 Agent 模式使用 null。Header 名不区分大小写，构造时复制为不可变 map，null map 视为空；null 键/值和大小写归一化后重复键抛 `IllegalArgumentException`。

当前只消费 `x-user-id`、`x-space-id`、`x-tenant-id` 的非空白值。其他 Header 不进入执行上下文，不自动透传到远端。调用方负责身份认证和 Agent/Task 访问授权，`Authorization` 不是自动认证或出站凭据。业务输入和参数放在 JSON-RPC 正文中。

```json
{
  "jsonrpc": "2.0",
  "id": "request-1",
  "method": "SendMessage",
  "params": {
    "message": {
      "messageId": "message-1",
      "role": "ROLE_USER",
      "contextId": "conversation-1",
      "parts": [{"text": "hello"}]
    }
  }
}
```

支持 `SendMessage`、`SendStreamingMessage`、`GetTask`、`SubscribeToTask`，与 HTTP 共享协议解析、准入及 SDK RequestHandler，不另建 Task。查询/订阅使用 `params.id`。新 Task 不填写 taskId；遇到 `TASK_STATE_INPUT_REQUIRED` 时，以新 messageId 和返回的原 taskId/contextId 再发送补充输入。同一 hosted Task 的后续请求必须选相同 agentId。

## 返回和线程约定

每个 `onNext` 是一个完整 JSON-RPC 响应字符串，没有 SSE framing。`SendMessage` 正常结果保留 SDK 的 `result.task` / `result.message` 包装，`GetTask` 的 `result` 直接为 Task，流式结果保留 `task` / `statusUpdate` / `artifactUpdate` 等 SDK 包装。

- `invoke` 调用时分发一次；`SendMessage` 默认可能阻塞。`params.configuration.returnImmediately=true` 按 SDK 提前返回，不能据此判定 Task 完成。
- `SendStreamingMessage` 在返回 Publisher 前已经提交执行。及时订阅，未订阅不代表未提交。
- 每个返回 Publisher 只能订阅一次；第二个订阅者收到 subscription 后收到 `IllegalStateException`，不会再次执行 Agent。
- 在可阻塞的工作线程调用和驱动订阅，按 `Flow.Subscription.request(n)` 消费。方法 API 不分配额外 Agent 线程池。
- 取消 subscription 停止本次结果消费，不取消 Task，不停止业务 Agent；流 complete 也不等于 Task completed，等待输入时同样会结束当前响应。
- JSON-RPC 错误作为单条 JSON 响应按 demand 发出。已建立流的失败走 `onError`，不重试执行。
- `openjiuwen.service.a2a.max-message-bytes` 同时限制方法入参 UTF-8 字节数，超限返回 `-32600 / Request too large`；HTTP 原 Content-Length/413 规则不变。
- Agent 初始化前和容器关闭后调用返回 `-32603 / Agent is not ready`。不要在 `@PostConstruct` 或 `ApplicationRunner` 中假设 `ApplicationReadyEvent` 初始化已完成。

关闭自带 HTTP 后，远端回调本地的 receiver 和本地 AgentCard 发布需由客户外层承接。callback body 不是上述四种 JSON-RPC 请求，不能直接交给 invoke。内存/Redis 继续使用已有存储配置，不新增跨进程 Task 执行迁移、历史事件回放或幂等承诺。
