# A2A 与平台边界

本文说明 **进程内 A2A**（单 Agent 镜像内）与 **平台级 A2A 服务**（多 Agent 路由）的边界。配置与端点见 [A2A 开发指导](开发指导.md)；与 lifecycle interrupt 的关系见 [生命周期与探针](../生命周期与探针.md)。

## 能力对照

| 项 | Agent Service（本仓） | 平台 A2A Service（规划） |
| --- | --- | --- |
| Agent Card | ✅ 配置驱动 | ✅ 平台级 Card 聚合 |
| JSON-RPC `SendMessage` / `SendStreamingMessage` | ✅ | ✅ 网关级 JSON-RPC |
| `GetTask` | ✅ | ✅ |
| Task 取消（Cancel） | ✅ | ✅ 平台级路由 |
| TaskStore（InMemory / Redis） | ✅ | ✅ 集中式 Redis |
| A2A Client（远端探测 + 委派） | ✅ | ✅ 平台级路由 |
| HTTP `/v1/query` | ✅ 并存 | ✅ 可转发至 `/query` 或 `/a2a` |
| 服务注册 / 目录 | ❌ | ✅ 消费 Manager 目录 |

本仓已交付 **进程内 A2A Server** 与 **出站委派 Client**（含中断-恢复）。

## 两种形态共存

| 形态 | A2A Server 位置 | 适用场景 |
| --- | --- | --- |
| **进程内 A2A**（本仓） | 与 Agent 同进程 | 单 Agent 镜像直连，无需平台 |
| **独立 A2A Service**（规划） | 独立平台进程 | 多 Agent 路由、统一网关、集中 TaskStore |

进程内 A2A 覆盖单镜像直连场景；平台服务额外提供跨 Agent 路由、限流与集中目录。

## 数据面 E2E

### 进程内 A2A（本仓）

```text
A2A 客户端
  → GET /.well-known/agent-card.json
  → POST /a2a/  SendMessage / SendStreamingMessage / GetTask / Cancel
你的 Agent Service
  → 执行 Agent → 返回 JSON-RPC 响应 / SSE
```

### 平台 A2A（规划）

```text
A2A 客户端
  → GET {a2a-platform}/a2a/.well-known/agent-card.json
  → POST {a2a-platform}/a2a/
平台 A2A Service
  → 目录：agent_id → backend_base_url
  → 转发 POST {backend}/v1/query 或 {backend}/a2a/
你的 Agent Service
  → 执行 Agent
```

## 与 Python 的对照

| Python 形态 | 角色 | 本仓对应 |
| --- | --- | --- |
| `applications/a2a_service` | 平台 A2A + 编排 | 进程内 A2A + 独立 A2A Service（规划） |
| `service/AgentApp` | `/query` + `/a2a` | 同左 |
