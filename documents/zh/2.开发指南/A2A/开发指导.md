# A2A 开发指导

本文说明每个 Agent Service 对外提供的 **A2A Server**（被别人调用）与 **A2A Client**（委派远端 Agent）能力：需要哪些配置、暴露哪些端点、以及委派时的可观测行为。平台级多 Agent 路由见 [A2A 与平台边界](平台边界.md)。委派时消息如何透传、哪条回喂模型见 [出站委派与流式规则](出站委派与流式规则.md)。

**前置阅读**：[HTTP 对话面](../HTTP对话面.md)（REST Ingress）、[生命周期与探针](../生命周期与探针.md)（Cancel vs lifecycle interrupt）。

## 概述

每个 Agent Service 实例基于 `org.a2aproject.sdk:1.0.0.Final` 提供：

- **A2A Server**：对外暴露 Agent Card 与 JSON-RPC 端点，供其它 A2A 客户端调用你的 Agent。
- **A2A Client**：按配置发现并委派远端 Agent（工具触发 `a2a_delegate`）。
- **TaskStore**：Task 持久化，InMemory 或 Redis。

```text
A2A 客户端                          你的 Agent Service
──────▶ GET /.well-known/agent-card.json   →  返回 Agent Card
──────▶ POST /a2a (JSON-RPC)               →  执行你的 Agent，返回结果 / SSE
```

引入 `agent-service-app` 时，A2A SDK 由模块传递依赖提供；一般 **无需** 在业务 POM 中重复声明 SDK 坐标。

## Maven 依赖（可选显式声明）

仅在需要直接引用 SDK API 时添加：

```xml
<dependency>
    <groupId>org.a2aproject.sdk</groupId>
    <artifactId>a2a-java-sdk-spec</artifactId>
    <version>1.0.0.Final</version>
</dependency>
<!-- server-common、jsonrpc-common、client 按需 -->
```

## 配置

Agent Card 的 `name` 取自 `spring.application.name`，`version` 取自 `openjiuwen.service.version`。其余在 `openjiuwen.service.a2a` 下：

```yaml
spring:
  application:
    name: "My Agent"

openjiuwen:
  service:
    version: "1.0.0"
    a2a:
      agent-description: "A helpful assistant"
      public-url: "https://my-agent.example.com"   # Card 中的对外 URL；可留空由请求推断
      is-streaming: true
      json-rpc-path: "/a2a"
      task-completion-timeout-seconds: 300
      skills:
        - id: search
          name: Search
          description: Search for information
      remote-agents:                                # 可委派的远端 Agent 目录
        - name: hotel-agent
          url: https://hotel-agent.example.com/a2a
          timeout-seconds: 300
```

出站 **Remote（A2A）** 也可通过 `openjiuwen.service.external.remote` 配置，与 `a2a.remote-agents` 是 **两条集成路径**，见 [Adapters 与 Handler](../Adapters与Handler.md)。

TaskStore Redis：配置 `openjiuwen.service.middleware.checkpointer.type: redis` 后，A2A 复用同一 Redis 连接持久化 Task。

### Callback 目标限制

开启 push notifications 后，入站 callback URL 校验和默认 sender 投递前校验使用同一规则：
仅接受 HTTP/HTTPS；默认拒绝回环、私有、链路本地、未指定、组播及共享地址空间等危险地址。
域名解析失败或任一解析结果被拒绝时，不投递 callback；默认 sender 不跟随 HTTP 重定向。

内网 Runtime 互调时，在**发送 callback 的 Runtime** 上配置
`openjiuwen.service.a2a.callback-allowed-hosts: [callback.internal, 10.0.0.8]`。
默认值为空列表。白名单按主机名或 IP 精确匹配（主机名忽略大小写，IPv6 使用方括号），不支持 URL、CIDR 或通配符，
不限制端口和路径。白名单主机跳过地址过滤，因此只能填写部署方控制的可信目标。
已有内网或本机 callback 部署升级时需要显式配置；未使用 callback 的调用不受影响。

该校验不锁定连接使用的 DNS 结果；防止 DNS rebinding 仍需部署侧出站网络限制。
HTTP/TLS 连接、认证头和 callback 内容继续使用现有 sender 逻辑。

## 自定义编排

默认编排已启用 A2A 委派。如需替换，提供一个 `ServeOrchestrator` Bean 覆盖默认实现：

```java
@Bean
ServeOrchestrator myOrchestrator(...) {
    return new MyCustomOrchestrator(...);
}
```

## A2A Server 端点

### Agent Card

`GET` 三个路径内容相同：

| 路径 | 说明 |
| --- | --- |
| `/.well-known/agent-card.json` | 标准 |
| `/.well-known/agent.json` | 兼容 |
| `/a2a/.well-known/agent-card.json` | 兼容 |

### JSON-RPC

`POST /a2a`（及 `/a2a/`）：

| 方法 | 模式 | 说明 |
| --- | --- | --- |
| `SendMessage` | 非流式 | JSON 单次响应 |
| `SendStreamingMessage` | SSE | `text/event-stream` |
| `GetTask` | 非流式 | 查询 Task 状态 |
| Cancel | — | 取消进行中的 Task，见「Cancel 与 interrupt」 |

流式 SSE 记录格式：

```text
event:jsonrpc
data:{"jsonrpc":"2.0","id":1.0,"result":{...}}
```

### Task 状态

```text
SUBMITTED → WORKING → COMPLETED / FAILED / INPUT_REQUIRED
```

`INPUT_REQUIRED` 表示 Agent 需要更多输入，客户端应带同一 `contextId` 再次请求以续接。

### 请求字段映射

入站 A2A 请求按下表映射到内部对话请求：

| A2A 字段 | 对话请求 |
| --- | --- |
| `message.contextId` | `conversationId` |
| `message.taskId` / `messageId` | 透传 |
| `message.role` / `parts[].text` | 消息内容 |
| `params.metadata` | `metadata` |

`taskId` 非空表示 resume（续接已有 Task）。`metadata` 会一路透传到被委派的远端 Agent，可用于跨 Agent 传递上下文。

## Cancel 与 interrupt（勿混淆）

| 机制 | 触发方式 | 作用 |
| --- | --- | --- |
| **A2A Cancel** | JSON-RPC Cancel | 停止当前进行中的 A2A 流 |
| **Lifecycle interrupt** | 运行时生命周期管理（无 REST 入口） | 停止当前流并触发中断处理 |
| **业务 interrupt** | Agent 在执行中发出中断信号 | 路由为委派（`a2a_delegate`）或向用户提问（`ask_user`） |
| **reset_conversation** | `POST /v1/reset_conversation` | 停止当前流并清理会话 |

详见 [生命周期与探针 · 三种中断语义](../生命周期与探针.md#三种中断语义)。

## 委派远端 Agent

当你的 Agent 在工具里触发 `a2a_delegate` 中断时，运行时按 `a2a.remote-agents` 目录找到目标 Agent 并发起调用，把远端结果回喂给你的模型继续对话。

- **透传与结果**：仅当目标在 `a2a.remote-agents` 中配置 `streaming: true`，且当前上游请求本身为流式时，客户端才会实时看到该远端 Agent 的过程事件；任一条件不满足时，下游只返回聚合结果供模型继续执行。完整规则见 [出站委派与流式规则](出站委派与流式规则.md)。
- **中断-恢复**：远端返回 `INPUT_REQUIRED` 时，运行时自动保存待恢复状态并向客户端抛出中断；下一轮同一 `conversationId` 的请求会自动续接，无需你手动维护状态。
- **配置**：目标 Agent 在 `a2a.remote-agents` 下声明；启动时探测其 Agent Card，失败约 30s 重试。

```yaml
openjiuwen:
  service:
    a2a:
      remote-agents:
        - name: agentb
          url: http://localhost:18091/a2a
          timeout-seconds: 300
```
